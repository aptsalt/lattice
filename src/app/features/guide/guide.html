Every feature, explained

Lattice answers questions about leave policy from a Neo4j knowledge graph and shows its work. This page walks through each control, badge and panel in the order you meet them. For the system design see Architecture.

1 · Asking a question

Everything that shapes a request lives in the composer at the bottom of the chat. There are no hidden settings.

⛁ Live Neo4j ▾ Data source
Live Neo4j runs Cypher against the database on every turn (latency is simulated in this demo). Offline snapshot reads resolved.json, an export of the same graph, so the assistant works without a database connection. The stats line and the status dot in the header show which one answered.
⌁ Hybrid ▾ Retrieval mode
How the first entities ("seeds") are found before the graph is walked.
  • Lexical: full-text match on entity names and aliases. Exact, but blind to paraphrase.
  • Vector: embedding similarity. Catches "time off" for "annual leave", can drift.
  • Hybrid (default): both lists merged with reciprocal-rank fusion.
  • Graph: hybrid seeds, then a deeper 3-hop traversal for questions that span the taxonomy.
Switching mode changes the matched entities, the subgraph and often the answer; the Trace tab shows which stages ran.
▭ Context Use conversation context
When on, a short follow-up such as "And in Canada?" is rewritten with the country, leave type and topic of the previous turn before retrieval. The rewritten question appears after resolved: in the stats line. Turn it off to treat every message as standalone.
✦ LLM answer Generate LLM answer
When on, the language model writes prose from the retrieved facts and passages only, with a citation after every claim. When off, you get the grounding facts verbatim as a list, which is useful for checking what the model would have been allowed to say.
Suggestion and follow-up chips
On an empty conversation the chips above the composer are good first questions. After each answer the chips become follow-ups that exercise context resolution ("And in Mexico?", "Who approves it?").

2 · Reading an answer

● confidence: high
A grounding score, not a probability. High: two or more entities in the question matched the graph and at least two rules back the answer. Medium: a single match; the answer tells you to check the sources. Low: nothing matched and the assistant says it cannot find that in the graph rather than guessing.
1 Citations
Every claim ends with a numbered chip. Hover for the section title, its position in the policy document and a snippet; click to open the Evidence panel on that passage.

Action rail
Copy the answer as markdown, regenerate it with the current composer settings, or rate it. Ratings are local to this demo.

3 · The Evidence panel

Open it with the Evidence button under any answer. It has five tabs; each one is a different lens on the same retrieval.

Subgraph
The slice of the knowledge graph the answer was built from. Nodes are entities, coloured by label (Country, Policy, LeaveType, Rule, Regulation, Approver…); edges are typed relations such as HAS_RULE or OVERRIDES.
  • Yellow ring: the answer relied on this node.
  • Dashed ring: retrieval matched this node to the question (a seed).
  • Plain: pulled in by the traversal but not used.
  • Focus dims everything the answer did not use.
Five views of the same subgraph: Force (physics layout; drag to pin, double-click to release, hover for properties and relation names), Radial (the taxonomy as a tree from World outward; dashed arcs are relations outside the tree), Orbit (a rotating 3D canvas; drag to turn), 3D (WebGL force graph; particles run along the edges the answer used; click a node to fly to it) and Replay (lights nodes up in the order the pipeline touched them). Your last choice is remembered.
Facts
Every (subject, relation, object) triple in the subgraph with the confidence stored on the relationship at ingestion. Rows with the yellow bar are the grounding facts; the checkbox hides the rest. Click a column header to sort.
Sources
The policy passages behind the grounding facts, numbered to match the citations. The breadcrumb shows where each section sits in its document (policy › chapter › section) and the tag shows which country policy it belongs to.
Cypher
The exact database queries this turn ran. Explained in full in the next section.
Trace
One row per pipeline stage: resolve, lexical, vector, fuse, expand, rank, cite, answer. Each shows what it did, how long it took and how many graph nodes it touched. This is the same data the Replay view animates.

4 · The Cypher tab

Cypher is Neo4j's query language, the graph equivalent of SQL. A pattern like (r:Rule)-[:CITED_IN]->(s:Section) reads "a Rule node connected by a CITED_IN relationship to a Section node". The tab shows the queries the FastAPI service sent to Neo4j for the current answer so an engineer can paste them into Neo4j Browser and reproduce the evidence by hand. Clause by clause:

@for (row of cypher; track row[0]) { }
{{ row[0] }} {{ row[1] }}

Lexical mode shows only the full-text query, vector mode only the vector query, hybrid and graph show both plus the expansion. In graph mode maxLevel rises from 2 to 3.

5 · Conversations

Sidebar
Only conversations live here, grouped by Today, Yesterday, Previous 7 days and Older. Search filters by title and message text. Hover a row to rename or delete it. The + button starts a new conversation.
Conversation menu (⋯)
Export downloads the thread as JSON including every answer's evidence. Clear empties the thread but keeps it in the list.
Persistence
Conversations, composer settings, theme and your preferred graph view are stored in this browser. Nothing leaves the page in the demo.
Theme
The sun/moon button in the sidebar footer switches between dark and light.
